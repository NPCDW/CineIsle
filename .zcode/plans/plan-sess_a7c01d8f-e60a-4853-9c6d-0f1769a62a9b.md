# Context

本地源码对比已确认：Android 发出的 JSON 符合 Yamtrack 的 `/webhook/custom/<token>`，而不是 multipart 的 `/webhook/emby/<token>`。开始返回 500 后 Android 仍保留同步会话，正常退出时会尝试发送 `stop`；结束失败不提示的直接原因是 `LoembyPlaybackCoordinator` 先清空 `current`，之后 `PlaybackScrobbler` 发出的错误无人接收。另有一个独立的 Yamtrack 服务端缺陷：`/root/Yamtrack/src/integrations/webhooks/base.py` 在动漫剧集分支使用了未赋值的 `tvdb_episode`，足以导致 500。按你的选择，本次只报告该服务端缺陷，不修改 `/root/Yamtrack`。

共享 `play_history.item_name` 目前由 Android 写入裸集名，而 loemby 写入 `S1E1. 集名`。当前项目指导文件还位于不会作为项目级说明加载的 `.zcode/AGENTS.md`，且混入大量互相覆盖的历史记录。

# Implementation plan

1. **先在当前已配置实机上复现并收尾**
   - 用 ADB 确认设备、实际包名和前台 Activity，保留现有日志后只点击一次播放。
   - 同时采集应用日志、Toast/Activity 状态和可获得的 HTTP 500 证据；日志中不输出 webhook URL、token、代理凭据或请求体。
   - 取证后使用播放器内返回或一次 Back 正常退出，等待结束结算并确认 `PlayerActivity` 已离开；在预期 `stop` 有机会执行前不 force-stop，确保实机不会继续播放。

2. **修复 Android 的 YamTrack 开始/结束诊断与提示**
   - 在 `domain/emby/playback/PlaybackScrobbler.kt` 保持“单个服务失败不阻断其他服务”和“开始失败仍可发送一次结束”的现有语义；复用现有注入式通知入口，增加仅含服务名、动作和 HTTP 状态的脱敏 `EmbyDiag` 日志。
   - 将第三方同步失败改为进程级、主线程安全的 Toast 通知，不再通过 `current?.callbacks` 转发，确保退出播放器后到达的 YamTrack `stop` 失败仍可见，也不会误投递给下一条播放会话。
   - 在 `di/DomainModule.kt` 提供唯一的 `PlaybackScrobbler` 单例和应用级通知器；移除 `di/DatabaseModule.kt` 中的重复注册。`LoembyPlaybackCoordinator.kt` 只继续收集 loopback 播放服务自身错误。
   - 增加回归测试：YamTrack 开始 HTTP 500 会提示但仍返回可结束会话；结束仍发送 `event=stop`、只发送一次；结束 HTTP 500 也提示；Trakt/Simkl/YamTrack 互不阻断，所有消息保持脱敏。

3. **统一完整集标题为 loemby 的 `S1E1. 集名`**
   - 在 Emby domain 新增唯一纯格式化函数：仅 Episode 且季/集号都存在时生成无补零的 `S1E1. 名称`；`S0E0` 等特别篇编号有效；缺号或非 Episode 保留原名；空名和已带同一前缀时避免悬空标点或重复前缀。
   - `PostgresAutomaticPlaybackWriter.kt` 直接根据 `EmbyItem` 计算 `item_name`，不再信任调用者传入的裸标题，使开始插入/更新和结束更新必然一致；不做历史全表回填，也不改 Room/PostgreSQL schema，旧记录在再次播放时自然更新。
   - 让 `EmbyViewModel.displayTitle` 委托给该函数，并覆盖真正展示“完整标题”的 Classic/Cine 搜索、详情、普通卡片、导航、播放器元数据与通知路径；YamTrack 的剧集 `title` 复用同一集标题片段后再加剧名。
   - 给 feed/兼容播放入口补齐 `itemType`、season、episode 元数据，保证 Emby 元数据补取失败时，播放器和共享历史仍能得到正确标题。
   - 保留原始 `EmbyItem.Name` 用于搜索、排序和模型数据；已经单独展示季集徽章的紧凑 Episode 卡、Cine episode rail、弹幕匹配、媒体源/音轨标题不重复添加前缀。
   - 更新纯格式化、共享历史 start/stop、主队列/兼容入口/feed、YamTrack payload 及 Classic/Cine 展示测试。

4. **重写项目级 `AGENTS.md`**
   - 新建正确位置 `/workspace/AGENTS.md`，完成后移除旧 `/workspace/.zcode/AGENTS.md`，避免两份来源。
   - 内容压缩为可执行的当前约束：项目定位与技术栈、单 `:app` 架构、Classic/Cine 共享业务、包名与 namespace、启动关卡、Room v22 与 PostgreSQL 职责、共享数据库写入白名单、Emby/loopback/追踪同步规则、已删除功能边界、编码与迁移规范、密钥安全、本地 `/root/loemby`/`/root/uosc`/`/root/Yamtrack` 参考规则、Dockerfile 同步要求、构建/测试/实机协议。
   - 保留“无设备必须询问而不能直接跳过”“优先 arm64 小包”“只使用本地参考仓库、不网页抓取”等有效要求；删除 APK 哈希、设备号、旧测试数量、过时架构、互相覆盖的 CRUD/只读描述和逐次会话日志，并明确以后不再把交付流水账追加到指导文件。

5. **验证与交付报告**
   - 运行相关定向 JVM 测试，再运行 `:app:testStandardDebugUnitTest`、`git diff --check` 和 `:app:lintStandardDebug`；若 lint 仍有既有错误，原样报告而不宣称通过。
   - 构建 `:app:assembleStandardDebug -Pabi=arm64-v8a`。如能保留当前实机配置，则安装后再次播放、观察开始错误、正常返回、观察结束错误并确认播放器退出；若安装会破坏已配置环境或签名不兼容，则停止安装并明确说明，绝不以强制停止替代结束调用验证。
   - 最终报告 Android 与 loemby 的实现差异、实机开始/结束调用证据，并单列 `/root/Yamtrack/src/integrations/webhooks/base.py` 的未赋值变量缺陷及 `/root/Yamtrack/src/integrations/tests/test_webhooks_jellyfin.py` 已表达但生产代码未实现的预期；不改动 Yamtrack、loemby，不提交或推送。
