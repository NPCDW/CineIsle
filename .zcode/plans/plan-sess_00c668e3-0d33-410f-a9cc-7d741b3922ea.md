# Context

这次修改解决四个相互关联的问题：loembyA 在同一 Yamtrack 实例上无法像桌面 loemby 一样同步电视剧集完成状态；共享 `play_history` 的部分写入没有同步 `update_time`；Android 当前仍读取、展示并实际使用 loemby 的正向代理配置；README 仍大量描述已移除的旧项目功能。

重新对比当前 `/root/loemby` 后，电视剧集请求的关键 Android 独有差异是：桌面端在播放结束时复用开始事件，只把 `played` 改为完成状态，因而第二次仍发送 `event: "start"`；Android 当前改成了 `event: "stop"`。按用户提供的“同一 Yamtrack 服务中桌面端正常”这一事实，以桌面行为为兼容契约，在 `/workspace` 内修复，不修改 `/root/Yamtrack`、`/root/loemby` 等参考仓库。

代理范围按已确认的选择处理：彻底忽略共享的普通 HTTP/HTTPS/SOCKS 正向代理，但保留 `reverse_proxy_server` 反向路由和必需的 `127.0.0.1` 进程内播放中继；不额外改变其他客户端对 Android 系统代理的既有行为。

## 1. 修复电视剧集 Yamtrack 同步

- 在 `app/src/main/java/app/marlboroadvance/mpvex/domain/emby/playback/PlaybackScrobbler.kt` 抽出可纯测试的 Yamtrack 请求体构造逻辑，并与桌面 loemby 对齐：
  - 开始播放发送 `event: "start"`、`played: false`。
  - 结束结算继续发送同一 `event: "start"`，只按桌面规则把 `played` 更新为 `progress > 80`。
  - 保留电影 ID、剧集 ID、系列 ID、季号/集号及标题的现有字段布局；不改 webhook URL，不伪造或迁移共享配置。
  - 不为完成写入启用通用 5xx POST 重试，避免不确定结果下重复标记。
- 增加不含凭据/URL/标题/具体 ID/响应正文的诊断：只记录阶段、媒体类型、HTTP 状态、季集号与各类 ID 是否存在、是否因载荷为空而跳过，便于实机判断请求是否发出；系列元数据读取失败不再完全静默。
- 在 `PlaybackScrobblerTest.kt` 和相关协调器测试中加入桌面兼容回归：精确校验剧集开始及完成请求、完成阈值、只结算一次、电影不回归、缺少身份时不误报成功、错误提示不泄漏 webhook/token。
- 保留当前工作树中已完成的通知器、标题和结算生命周期改动，避免覆盖用户已有修改。

## 2. 对齐共享播放记录的更新时间

- 保留 `PostgresAutomaticPlaybackWriter.kt` 已有行为：新增记录同时写 `create_time`/`update_time`，开始和停止更新 `update_time`；系列 pin 交接仍按 loemby 只改 `pinned`。
- 在 `JdbcPostgresPlaybackHistoryMarkWriter` 的受限 CAS 标记循环中，将 `pinned` 和服务器生成的 `clock_timestamp()` 放在同一条 SQL 中原子写入，并用 `RETURNING update_time` 取回已提交时间；继续保留行 ID、服务器 ID、旧 pin 值谓词、单次写入和未知提交结果只读核对，绝不补写或盲目重放。
- 扩展 `PostgresPlaybackHistoryMarkResult.Committed` 携带更新时间；`PlaybackHistoryViewModel` 在成功或只读核对后只合并目标行的 `pinned` 与 `updateTimeMs`，不导入并发变化的其他元数据、不重排或重填当前页。
- 更新 `PostgresPlaybackHistoryBackendTest.kt`、`PlaybackHistoryViewModelTest.kt`、`PostgresAutomaticPlaybackWriterTest.kt`，覆盖 SQL/参数、时间字段、冲突、缺列、取消及 commit-unknown 场景。
- 在 `AGENTS.md` 中仅更新耐久边界：CAS 标记能力包含与其耦合的服务器生成 `update_time`，不扩展为任意时间戳或通用 SQL 写入能力。

## 3. 移除共享正向代理的读取、展示和使用

- 在 `PlaybackConfigurationRepository.kt`：
  - 从 `ANDROID_GLOBAL_CONFIG_ALLOWLIST` 删除 `global_browse_proxy_id`、`global_play_proxy_id`、`trakt_proxy_id`、`simkl_proxy_id`、`yamtrack_proxy_id`。
  - 删除 `proxy_server` 查询、代理凭据模型、引用解析和 URL 拼装；运行时配置不再持有 browse/play/tracker proxy。
  - `emby_server` 快照不再读取或校验 `browse_proxy_id`/`play_proxy_id`，桌面端修改代理不会使 Android 播放快照失效。
- 在 `EmbyServer.kt`、`PostgresEmbyStore.kt` 中移除普通代理字段和必需列，改用明确字段投影，确保服务器/线路加载不传输这些代理值；保留线路身份、已应用的服务器 URL 与 `reverse_proxy_id`。
- 在 `LoopbackHttpPool.kt` 删除正向代理参数、代理客户端分桶、HTTP 代理认证和自定义 SOCKS socket 实现；同步清理 `LoopbackPlaybackServer.kt`、`LoopbackSubtitleCache.kt`、`LoembyPlaybackCoordinator.kt`、`PlaybackScrobbler.kt` 的所有代理实参。该播放池在无共享代理时继续使用现有直连策略。
- 在 `SharedConfiguration.kt` 和只读设置入口中删除全局/服务器/Trakt/Simkl/YamTrack 代理行及整个“代理服务器”区块，改为只显示线路与反向路由；保留页面只读、来源代次和脱敏约束。
- 更新资源文案、设置搜索索引及代理相关测试，重点断言：没有 `FROM proxy_server`、代理键不在 allowlist、陷阱代理凭据不会被读取、第三方同步与媒体请求不再接收共享代理、反向路由测试保持通过。
- 不删除或改名本地 loopback 中继，也不把 unrelated 的 Java reflection `Proxy`、Binder proxy、旧 ISO 拒绝标记误当网络代理。
