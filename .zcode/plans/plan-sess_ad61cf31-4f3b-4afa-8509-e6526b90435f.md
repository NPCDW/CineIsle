## Context
在刚才已删除直播、播放列表和 DLNA 的基础上，继续删除**远程 ISO 播放**。清理专用解析/代理代码及依赖，避免删除代理后仍把已知 ISO 原文件交给普通播放器；保留普通 Emby 视频、剧集连播、身份头及现有修改。

## 实施方案
1. **删除远程 ISO 专用模块**
   - 删除 `domain/iso/` 的远程 ISO、ISO9660/MPLS 解析、分段映射、HTTP Range Reader 和本地代理六个文件，以及该目录的五个专用测试。
   - 清理 `EmbyViewModel.kt` 的 ISO 探测预算、探测/解析方法、代理 URL 和续链逻辑。
   - 继续复用普通 `resolveIfEnabled`、直链探测与 `launchSingle` 起播逻辑，保留普通 HTTP Range、重连和身份头。

2. **清理播放器及漏入口**
   - 删除 `PlayerActivity.kt` 中仅针对 ISO 代理的 seek 提示及调用；保留正常拖动、上下集、重试和播放器交接。
   - 修改 `GsyPlayerActivity.kt`：已知远程 ISO 不再自动转交 mpv。
   - 在 Emby 单播、临时队列、外部播放器、视界流初始/续拉及播放器 URI 入口接入轻量媒体源级判断，已知 ISO 原文件明确提示不支持，不启动解析、代理或原文件播放。
   - 判断依据为选中媒体源的 Container/Path 和已取得的 URL；不为识别 ISO 恢复扇区探测。含 ISO 和 MKV 等多版本的条目仍可浏览并播放普通版本，显式转码返回普通视频流仍保留。
   - 保留 `PlayerUtils.isoPlayableUri()` 的**本地文件 ISO**处理，本次范围仅为远程 ISO。不透明 URL 且无 ISO 元数据的媒体无法可靠识别，不宣称全面识别所有镜像。

3. **删除不再使用的依赖和说明**
   - DLNA 已删除，NanoHTTPD 当前只剩 ISO 代理使用，因此移除 `app/build.gradle.kts` 的依赖、`gradle/libs.versions.toml` 的版本/别名、关于页致谢及中英文专用文案。
   - 更新 README 当前能力描述和项目最新记录。不改无关 Manifest 权限、普通网络配置或历史版本说明。
   - 不改 Room21、迁移/schema，不清播放历史或其他用户数据，不写 PostgreSQL。
