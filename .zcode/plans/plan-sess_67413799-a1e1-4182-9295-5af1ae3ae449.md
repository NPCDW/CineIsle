## Context
当前数据库已保存完整 Emby 客户端身份，但 API 缺少独立身份头，图片、普通播放、视界流、ISO、预取等链路还存在硬编码 UA 或身份上下文丢失。这次统一本应用控制的 Emby 请求，保留现有 PostgreSQL 只读配置、内存认证会话和反向代理行为。

已按你的选择限定范围：**本应用全面补齐；外部播放器传兼容请求头但不承诺其采用；DLNA 保持现状，不在六头保证范围；不新增媒体代理。**

## 1. 统一请求身份与 JSON POST
建立唯一请求头工具，复用 `EmbyServer.authIdentity`、`EmbyHttp.sessionServer()` 与 `EmbyEndpoints.belongsToServer()`：

| HTTP 请求头 | 配置来源 |
|---|---|
| `X-Emby-Token` | `apiToken`（现有行级内存登录会话有更新时使用有效 token） |
| `X-Emby-Client` | `client` |
| `X-Emby-Device-Name` | `device` |
| `X-Emby-Device-Id` | `deviceId` |
| `X-Emby-Client-Version` | `clientVersion` |
| `User-Agent` | `userAgent` |

- 不硬编码 loemby 身份，不替换数据库中的空值；登录前 token 为空时仍保留该头为空。
- 保留现有 `X-Emby-Authorization` 与 URL token 兼容行为。
- `USER_AGENT`、`CONTENT_TYPE` 按标准 HTTP 名称发送为 `User-Agent`、`Content-Type`，不发送下划线字面头名。
- 所有 **Emby POST** 使用 `application/json; charset=UTF-8`；统一 RequestBody 构造，空/空白请求体变成 `{}`，已有非空 JSON 保持原内容。
- POST 规则不应用到 DLNA SOAP、更新、弹幕等非 Emby 请求。
- `EmbyHttp` 每次实际网络交换按目标地址应用六头；跨域 CDN 不携带 Emby token、Authorization 和设备身份头，UA 保持与预解析一致。重定向回 Emby 时重新应用身份。
- 保留原有超时、GET/HEAD 重试、401 行级认证和 `warmStream` 不跟重定向的策略。

主要文件：`domain/emby/EmbyClient.kt`、`EmbyHttp.kt`，以及一个共用身份/请求策略工具。数据库无需迁移或写入。仓库指定的 `/root/loemby` 当前不存在；批准后按仓库指引获取 main 参考源码，仅作实现核对，不运行其脚本。

## 2. 图片链路保留所属服务器
- 在生成/加载图片的链路中显式保留所属服务器上下文，避免只剩 URL 后从“当前服务器”猜测身份。
- 覆盖封面、背景、Logo、原图重试、照片 Coil Fetcher、调色板、拼图/预加载、播放器缩略图及 Widget。
- 普通页面可用页面级上下文减少参数透传，异步预热和非页面入口显式传入；多服务器卡片始终绑定各自的行。
- 缓存和并发下载键包含来源/服务器身份，避免同源不同账号或设备身份混用。
- 自定义服务器图标只有目标属于该 Emby 时才附加身份；第三方图标和 data URI 继续保持公共/本地加载。

代表文件：`components/EmbyImageLoader.kt`、`EmbyImage.kt`、`EmbyServerIcon.kt`、`photo/EmbyPhotoImageLoader.kt`、相关页面/卡片调用点、`widget/EmbyContinueWatchingWidget.kt`。

## 3. 主播放器、切集和辅助网络请求
- `EmbyViewModel` 单片与播放列表无论是否预解析，都交接所属服务器及完整请求上下文。
- 复用 `PlayerHandoff.headers`、`embyServerId` 和 `EmbyRepository.sessionSnapshotById()`；不序列化包含密码的服务器对象。
- 抽取共享 header 数组解析：处理全部完整键值对，不再假定第一对必须是 UA，也不丢失第一对。
- mpv 在起播、切集、重试和新 Intent 加载前应用当前 URL 的头；避免切集仅设置 Referer、或 FILE_LOADED 后按旧 URL 覆盖。
- GSY 每次 `setUpCurrent()` 按当前条目计算头；切内核保留交接信息。
- 重试探针、两条下一集预取、原生时长探测、文件名 HEAD、MediaInfo 的网络读取均接入同一策略；切到非 Emby/本地地址时清除旧身份。
- 删除或脱敏包含 token/完整认证头的日志。
- 不顺带改造播放会话 ID、媒体源选择或其他与本需求无关的播放逻辑。

主要文件：`EmbyViewModel.kt`、`PlayerActivity.kt`、`GsyPlayerActivity.kt`、`PlayerHandoff.kt`、`utils/media/HttpUtils.kt`、MediaInfo 交接入口。

## 4. 视界流、ISO、字幕与外部播放
- 视界流启动和续页绑定具体服务器，避免续页跟随全局选择而混入另一台服务器；Exo 和备用 mpv 使用完整六头，重新加载时更新。
- ISO 将服务器请求上下文贯穿 `RemoteIsoPlayback → HttpRangeReader / IsoRangeProxy.Route`，覆盖长度探测、Range 读取和续链，替换固定 Chrome UA并复用逐跳认证过滤；保留各自超时预算。
- 现有字幕 API 随公共请求工具自动覆盖；HTTP 外挂字幕按字幕自身 URL 判断归属，必要时先通过受控请求读取为临时字幕，避免依赖媒体全局头。
- 外部播放器 launch/chooser 发送常用的 header extras；DLNA 不修改。

主要文件：`feed/FeedViewModel.kt`、`VerticalFeedActivity.kt`、`ExoPlayerPool.kt`、`FeedMpvEngine.kt`、`domain/iso/RemoteIsoPlayback.kt`、`HttpRangeReader.kt`、`IsoRangeProxy.kt`、`ExternalPlayers.kt`。

**技术边界：**本应用可确保构造和交接完整请求头，OkHttp 可逐跳约束凭据；mpv/GSY/Android/MediaInfo 原生内部重定向和派生请求仍需实际验证，不能以 Kotlin Map 存在六头宣称每一跳已验证。若内核无法正确处理，将明确报告限制，不暗中新增代理或发送凭据到第三方。
