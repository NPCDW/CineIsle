## Context
目标是让应用只播放 Emby 来源的媒体，彻底删除系统传入任意文件/链接的播放能力和本地视频、音频、ISO 播放能力，同时保留 Emby 调用系统外部播放器。

当前本地浏览、扫描和下载业务已删除，但 `PlayerActivity` 仍导出并注册 VIEW/SEND/媒体链接，mpv、GSY 仍接受本地 URI 和通用播放输入，仅删除清单入口不够。

### 范围边界
未收到补充问题的回答，采用以下范围供本次审批：
- 删除本地外挂音轨加载，保留 Emby 内嵌音轨切换。
- 保留外挂字幕、字幕字体和 mpv 配置的 SAF 读取；这些不属于本地主媒体播放。
- 独立 MediaInfo 是分析而非播放，本次不删除其页面、入口或依赖，避免扩大任务。
- 不删除用户文件，不清空旧历史，不修改 Room schema、PostgreSQL 业务或原生解码库。

## 实施方案
### 1. 关闭系统通用播放入口
修改 `app/src/main/AndroidManifest.xml`：删除 `PlayerActivity` 的全部媒体 VIEW/SEND/BROWSABLE/AppLink filters，改为 `exported=false`。保留 Emby 内部显式启动、媒体服务、PiP，以及用于发现 MX/VLC 等播放器的 `<queries>`。

### 2. 统一 Emby 主媒体输入规则
在 `ui/player/` 增加可测试的共享输入策略，复用 `PlayerHandoff.read`、`EmbyRepository.sessionSnapshotById/sessionServer` 和 `EmbyMediaSourcePolicy`，接入 `PlayerActivity.kt` 与 `GsyPlayerActivity.kt`：
- 新播放必须有有效绑定 Emby 服务器、条目上下文，以及有效 HTTP(S) 媒体地址；队列逐项检查地址及 ItemId 对应关系。
- 拒绝 file/content/fd/data、裸路径、通用流协议及无 Emby 上下文的 HTTP(S) 起播。
- 冷启动、新 Intent、默认内核转交、切内核、切集和重试保持同一规则；检查先于播放器初始化或加载。
- 不用域名限制 Emby 来源，保留关联第三方 CDN、反代、普通 loopback 流、请求头及现有远程 ISO 拒绝策略。
- 通知/PiP 的无内容 Intent 只恢复已有会话，不覆盖旧 Intent 或重新加载媒体；无会话冷启动不允许起播。
- 核对视界流的 Emby 取流路径，避免遗留通用本地起播入口。

### 3. 删除本地播放实现
重点修改 `PlayerActivity.kt`、`GsyPlayerActivity.kt`、`PlayerUtils.kt`、`PlayerHandoff.kt`：
- 删除 `file_path`、备用通用 URI、分享 stream/text 的主媒体解析与兼容返回协议。
- 删除本地 ISO 探测、光盘 URI、自动切 mpv、本地路径转换、文件缺失检查、MediaStore 本地时长和本地媒体标识分支。
- 删除无调用的 GSY 通用起播工厂及清理后无引用的 `utils/media/MediaIdentifier.kt`。
- 保留 Emby 内部队列、进度、版本、身份头、双内核交接、本机自动播放状态和网络缓存。
- `openContentFd` 仍被 `utils/media/SubtitleOps.kt` 使用：保留附件读取，不再用于主媒体起播。

### 4. 清理相关 UI 与当前功能描述
- 修改 `PlayerSheets.kt`、`PlayerControls.kt`、`AudioTracksSheet.kt`、`PlayerViewModel.kt`，删除本地外挂音轨选择器及 `audio-add` 调用链，保留内嵌音轨设置和字幕能力。
- 清理无消费者的文件浏览设置、权限引导和旧文件卡片代码；保留 Emby 列表滚动条、已看阈值和仍被人物页使用的 `CineSearchField`。
- 同步两份设置搜索索引、中英文资源，以及 README/网站/商店中涉及本次已删除播放能力的当前描述；不重写历史发布记录。
- 保留 `ui/browser/emby/ExternalPlayers.kt`、Emby 外部播放器选择弹窗及 Classic/Cine 详情调用链。
