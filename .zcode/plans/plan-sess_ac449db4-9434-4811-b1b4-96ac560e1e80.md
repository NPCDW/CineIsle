## Context
在已完成的两层框架上接入内层搜索、外层聚合检索和 PostgreSQL 播放历史。用户已批准上一版方案，并追加允许按 loemby 修改历史的置顶/隐藏标记；这是本次唯一新增的 PostgreSQL 写入例外。

## 1. 内层搜索
- 提取原 `EmbyHomeScreen.kt` 首页搜索页面，保留输入、清空、键盘搜索、类型筛选、结果分类、海报、搜索历史与截断提示，接入内层底栏“搜索”。
- 只搜索进入的服务器；移除 Classic 首页搜索按钮/搜索分支，以及 Cine 手机和宽屏首页的搜索按钮、搜索胶囊。
- Classic/Cine 共享搜索功能，沿用主题和现有卡片组件；保留返回与底部留白。

## 2. 外层聚合检索
- 复用内层搜索控件，对所有启用服务器发起请求；组顺序跟随服务器列表，不按完成时间重排。
- 每组第一行左侧图标和服务器名、右侧状态图标；第二行横向海报结果，或加载提示、失败原因、空结果。
- 分别展示加载、失败、成功有结果、成功空结果；部分请求失败时保留已有结果并明确提示，不伪装为空结果。支持单组重试。
- 停用服务器不请求；启用但配置无效的服务器仍显示失败组。
- 约 400ms 防抖、键盘立即搜索、最多同时查询 4 台服务器、有界结果和超时。分类切换仅本地筛选。
- 搜索使用明确的服务器会话，不在请求时切换当前服务器、不写凭据。补齐失败保留、实际 OkHttp Call 取消、取消后停止重试，以及来源/请求代数隔离。

## 3. PostgreSQL 播放历史
参考 `/root/loemby/src/page/History.vue`、`src-tauri/src/mapper/play_history_mapper.rs` 和 PostgreSQL 迁移定义。
- 新增历史模型、Store、仓库、ViewModel 与手机列表页面，替换外层占位。
- 从 `play_history` 查询服务器、剧集/影片/集名、播放时长、时间和 pinned；支持服务器/剧名/集名筛选、总数、刷新、每页 30 条分页。
- 沿用桌面 `pinned DESC, update_time DESC` 排序与名称筛选语义，增加记录 ID 稳定排序末项；COUNT/页查询使用相同条件及同一读取事务。
- 手机采用紧凑卡片；剧集/条目点击进入对应服务器详情。播放时长不是续播点，续播沿用详情里的现有逻辑。
- 加载、空结果、失败、分页重试区分清楚。服务器已失效的历史保留显示，不错误打开其他服务器。

### 用户追加：允许置顶/隐藏修改
- 按 loemby 循环切换：`pinned=0` 普通 → `1` 置顶 → `-1` 隐藏 → `0` 普通。
- “隐藏”保持桌面现有语义：记录仍可见，有隐藏标记并排序靠后，不删除记录。
- 修改仅限指定历史记录的 `pinned` 字段，不修改播放时长、更新时间、服务器配置、凭据或其他字段。
- 新增隔离的历史标记写事务入口，不放宽现有 SELECT-only 读取连接。既有 `PostgresExecutor.read()` 和服务器配置查询保持只读。
- prepared UPDATE 绑定历史 ID、服务器 UUID 和旧标记值，更新前后验证数据库来源；防连点和并发覆盖，成功提交后刷新当前页。冲突或提交结果不确定时明确提示并重读，不自动重放写操作或假报成功。
- 不增加删除、清空、手动进度修改、建表/迁移、历史新增或其他 PostgreSQL 写入。安卓自动播放上报链路保持不变。

## 4. 跨服务器身份与导航
- 聚合结果和历史携带不含凭据的来源/服务器 UUID/revision 引用；图片、详情、人物作品和后续播放绑定其来源。
- 复用现有详情/人物/媒体库/播放实现，补齐引用解析及后续传递；来源变化或服务器失效显示错误，不静默换服务器。
- 列表键包含服务器身份；凭据和大结果列表不进入 SavedState。

## 验证
- 搜索：单服务器范围、停用排除、无效组、稳定排序、有界并发、失败/空结果/部分失败、重试、防抖、实际取消、旧结果丢弃和来源隔离。
- 历史：查询字段/筛选/计数/分页/排序、孤立记录、时间与空值；标记循环、仅更新 pinned、提交成功/失败/冲突/未知结果、来源切换、读取仍只读且其他写入不存在。
- 不同服务器相同 item ID 的图片、详情和播放绑定正确；聚合查询不改变服务器选择、不写凭据。
- 单 ABI arm64 Debug/Release 构建、相关及完整单测、Lint；既有失败如实报告。
- 实机覆盖 Classic/Cine、明暗主题、搜索按钮移除、搜索与分组状态、历史筛选分页和标记操作、详情返回及底栏留白。安装前确认；无设备询问，未验收项明确标注。
- 默认用 fake JDBC/HTTP 做读写回归，不擅自连接真实数据库执行标记修改或调用全部真实服务器；真实端到端测试另行确认目标和授权。
