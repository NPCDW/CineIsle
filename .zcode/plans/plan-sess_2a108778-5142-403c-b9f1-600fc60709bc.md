## Context
将 loembyA 当前版本改为 `0.1.0`，并让继承自 mpvEx 的 GitHub 发布工作流与当前 Android 构建配置一致。保留已有工作区改动和草稿发布行为，不恢复已删除的 `.bak` 文件。

## 修改方案

### 1. 版本配置 — `app/build.gradle.kts`
- 将权威 `versionName` 从 `1.6.14` 改为 `0.1.0`。
- 将基础 `versionCode` 从 `236` 递增为 `237`；复用现有 `androidComponents` ABI 编码规则，arm64 最终为 `2372`，不重置安装升级序号。
- 不修改应用 ID、namespace、flavor、签名身份或运行时业务逻辑。

### 2. 发布工作流 — `.github/workflows/release.yml`
- 保留 `v` 版本标签触发和 `contents: write`；构建前检查标签版本与 Gradle 中的版本名一致，不允许 APK 版本与附件命名脱节。
- 对齐现有 `dev-android-Dockerfile` 工具链：JDK 21、Android Platform `37.0`、Build Tools `36.0.0`。使用 runner 的 SDK 路径，通过 `sh` 调用项目 wrapper，不修改其执行位、不添加 `--max-workers`。
- 仅构建 `:app:assembleStandardRelease -Pabi=arm64-v8a`，移除本工作流中的 Play Store、F-Droid 和 universal/其他 ABI 发布步骤；不删除项目中这些构建变体。
- 保留构建后签名方式，复用现有四个 secret 名称：`SIGNING_KEYSTORE`、`SIGNING_KEY_ALIAS`、`SIGNING_STORE_PASSWORD`、`KEY_PASSWORD`。通过环境变量传递材料和口令，使用临时 keystore 并保证失败时清理，签名策略与当前 release 配置一致。
- 检查 APK 的包名、版本、ABI、签名和对齐；将附件命名为 `loembyA-arm64-v8a-v0.1.0.apk`，生成 SHA-256 校验文件。
- 更新 release 名称、正文和附件列表为 loembyA；附件缺失时失败。保留 `draft: true`，带预发布后缀的标签标为 prerelease。
